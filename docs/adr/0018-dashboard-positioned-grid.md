# The dashboard layout is a positioned two-dimensional grid

**Status**: accepted. Supersedes [ADR-0017](./0017-dashboard-grid-fills-rows-by-stretching.md).

The dashboard's discrete sizes (`small`, `medium`, `full`) placed on a fixed six-column grid could not tile: arbitrary mixes left holes, and ADR-0017 patched those holes by stretching the last widget of a partial row. That stretch made a widget's rendered width differ from the tier it named, and a per-column minimum width — the obvious fix for an illegible `small` on a narrow main column — propagated its min-content up through the grid and pushed the whole main column into horizontal scroll. The one-dimensional model was the ceiling.

The layout model is therefore a **positioned two-dimensional grid**: each Dashboard widget carries a placement (`x`, `y`, `w`, `h` columns/rows) on a twelve-column grid, rendered by **`react-grid-layout`** in controlled mode with **snap-to-cell** — not a continuous freeform canvas — and with **vertical compaction**, so widgets float up and no vertical hole is ever left. A Widget definition declares a **size preset** (`small`/`medium`/`full`) that seeds a new instance's placement and doubles as a keyboard-resize step, plus optional per-definition `min`/`max` bounds; the definition, not the stored instance, owns the legibility floor, so it can evolve like the definition's other defaults. There is a **single canonical layout** (the desktop arrangement), and below the `md` breakpoint it collapses to one column; no per-breakpoint layout is stored. The instance's `size` field is replaced by its placement, and the array order stops being the model: a widget's position is its placement, not its index in a list. Because the feature has never shipped, the stored JSON shape changes with **no migration**.

**Considered options.** Preset-only resizing (Looker, Salesforce dashboards) is simpler and accessible but gives up the free placement the dashboard is being redesigned for; a custom grid engine on `@dnd-kit` + `react-resizable` re-implements collision and compaction forever for no UX gain and rides a pre-1.0 toolkit; `gridstack` is the credible framework-agnostic engine but owns the DOM and offers only column-count responsiveness rather than a storable layout. `react-grid-layout` is the de-facto engine (Grafana, Metabase, Kibana, HubSpot, Monday) and its persisted shape *is* the model above. The cost is a real dependency (with its `react-draggable` transitive) and a stored shape that is positioned rather than ordered.
