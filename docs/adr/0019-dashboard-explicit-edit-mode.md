# The dashboard has an explicit edit mode

**Status**: accepted. Supersedes [ADR-0016](./0016-dashboard-always-arrangeable-auto-save.md). The toggle and the add control became floating buttons in [ADR-0021](./0021-dashboard-actions-as-floating-buttons.md).

ADR-0016 kept the dashboard always arrangeable — every card's controls always mounted — because every arrange action is reversible and an edit/commit mode costs a place you enter and leave. That reasoning held while arranging was only drag-to-reorder among discrete sizes. It stops holding once arranging means dragging a positioned grid with resize handles: a visible grid and corner handles on an always-live dashboard are visually noisy and give the read surface a permanent authoring state. Every serious comparable dashboard (Grafana, Metabase, Sentry, Datadog, Power BI, Shopify, GA4) gates arranging behind an edit mode, and accessibility guidance warns against an always-draggable grid.

The dashboard therefore has an **explicit edit mode**. Outside it the dashboard is a clean, fully interactive read surface. Inside it, the grid becomes visible and the spatial controls mount: drag-to-move, resize handles, and the remove control. The non-spatial controls — renaming a widget's title and the config gear — stay available in both modes, since they do not clutter the surface and are authoring of a widget's content rather than its place. Edit mode is entered and left by a single low-key control in the dashboard header (a ghost Modifica/Fine button beside the save indicator); editing remains **auto-saved** with the existing debounce and indicator — dropping the mode switch does not reintroduce a Save/Cancel pair. Adding a widget stays outside the mode: a persistent bottom-right `+` control opens the permission-filtered Widget library and drops the new instance into the first free slot.

**Considered options.** Keeping "always arrangeable" (ADR-0016) was rejected: the 2-D grid's chrome does not belong on the read surface. Gating *everything*, including rename and config, was rejected as unnecessary — those controls are not spatial. Putting the add control behind edit mode too was rejected in favour of the always-present `+`, since adding is additive and reversible and the `+` is the discoverability anchor.
