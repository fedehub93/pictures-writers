# One box, two fields: Size and Spacing over one class and one set of variables

**Status**: accepted

The `Dimension` field held thirteen controls and two ideas. It was the box's own size — width, height, max width, min height, aspect ratio — and the space around and inside it, the four margins and four paddings, under a name that described only the first half. It was the only style concept in the Puck layer whose name stopped at half its contents: `DimensionProps` carried margin and padding, `getDimensionVars` emitted them, and every block declared the one accordion. Two consequences followed. An author who wanted padding opened a section called *Dimension*, which does not suggest it, and no other section offered it, so the control was reachable only by guessing. And the type carried `top`, `left`, `right` and `bottom`, which the stylesheet reset and consumed while no control could author them: there is no Position field, so they were dead keys and dead rules.

We split the authoring surface and the stored shape in two, and left the rendering contract exactly as it was. **Size** holds width, height, max width, min height and aspect ratio; **Spacing** holds the four margins and the four paddings, as two labelled groups. `size` and `spacing` are now the names in the panel, in props, in types and in the getters — `SizeProps`/`SizeField`/`getSizeVars`, `SpacingProps`/`SpacingField`/`getSpacingVars`, the last two in `src/puck/utils/get-style-vars.ts`. All sixteen blocks and the document root declare both, in the order block-specific fields → Layout → Size → Spacing → Typography → Decoration (Layout → Size → Spacing → Decoration on the root, where the Header's sticky switch stays last). Both are the same kind of surface as before: an accordion, one state per Breakpoint, a reset per property, the same unit presets, values cascading from the wider Breakpoint. The split therefore changes where a control lives and nothing about how it behaves, and the two sections open and close independently. The four dead offsets leave the type and the stylesheet; restoring them is part of a Position field, not of either field.

It is one element, not two: **one element, one reset scope, two authoring surfaces**. The block root still carries one class, `.puck-dim`, and the same Style variables, because the class is not the twin of a field. It is the box scope: at each Breakpoint it resets the thirteen variables to `initial` and consumes them as width, height, max width, min height, aspect ratio and the eight margins and paddings, so a value authored on a parent never leaks into a block that did not author it (see `src/puck/styles/puck-base.css` §1). A class named after either field would be wrong on the other's behalf, and renaming it would touch every block root for no behavioural change; `.puck-dim` stays, and the stylesheet and this record are where the name stops being surprising. The variables keep their names for a plainer reason: each is named after the CSS property it feeds — `--mt` is `margin-top`, `--pl` is `padding-left` — so none of them ever carried a field's name, and the four dead offsets are the only ones that leave.

The render path reads `size` and `spacing` only, with no fallback to `dimension`. A per-property fallback would be a correctness bug rather than a safety net, because absence in this pipeline does not mean "unknown": it means inherit from the wider Breakpoint, and the reset dot means the author deleted the value. `getSizeVars` reads an empty tablet width as "nothing decided here" and lets the desktop value cascade down; a stale `dimension.width` consulted for that breakpoint would put back a value the author removed. Once both shapes are allowed a stored document cannot distinguish "never authored" from "authored then deleted", so the fallback would have to guess, and it would guess wrong exactly where the reset matters.

Every stored version was migrated, not only the current and live ones. `PageVersion` and `SiteRegionVersion` both keep history, and a version is what a publish, a restore or a future version-history feature reads: a document left in the old shape is a page that renders without its spacing, found at the worst moment. The transform is shape-based rather than type-based, acting on any `props` object holding a `dimension` key, so it reaches the document root — which has props and no `type` — and blocks nested in slots and zones; the runner in `src/puck/migrations/migrate-size-spacing-documents.ts` is the only server-side piece, `scripts/migrate-puck-size-spacing.ts` drives it with a dry run, and a second run is a no-op. One subtlety the dry run surfaced. An authored `dimension` replaced the block default as a whole, so the transform writes **both** destinations even when one keeps no key: a Top bar with a height and no padding suppressed the default padding too, and writing only `size` would have brought `TOP_BAR_DEFAULT_SPACING` back on all 23 stored Top bar versions that authored a height.

`size` here is the box as the layout sees it — width, height, max width, min height, aspect ratio — and has nothing to do with the XS–XL button size rejected in ADR-0043: that field was rejected because it wrote padding and font size, which Spacing and Typography author. The field ADR-0043 calls Dimension is now Size, and the rejection it records stands under the new name. ADR-0043 and ADR-0039 are not revised: they were accurate when written, and this record carries the rename forward.

## Considered options

- **A panel-only split: two accordions over one `dimension` prop.** Rejected: it fixes findability and leaves the model defect untouched. The type, the getter and the stored shape would still be named after half their contents, and a field added to either half later would have to guess which half of the name it belongs to.
- **Keep one prop and relabel the field neutrally ("Box").** Rejected: the least informative of the options. A neutral label still makes the author scan thirteen controls in one section, names the element rather than the two decisions inside it, and keeps a getter that emits both concepts.
- **A per-property fallback to `dimension` in the render path.** Rejected: absence already means inherit, so it resurrects a value the author deleted, and it makes "was this value reset or never authored?" unanswerable by construction.
- **A whole-object fallback, expand/contract across two releases** (read `dimension` only when both `size` and `spacing` are entirely absent). Rejected for this work: it is safe against the reset trap, but it buys a compatibility window with a second release, a second code path and two shapes alive in the renderer. The order below is the cheaper trade; this remains the fallback if the deploy window is unacceptable.
- **Renaming the class to `.puck-box` and the variables to match.** Rejected: the class resets and consumes the box, so its name describes behaviour the fields do not have; a rename would touch every block root, the stylesheet and the tests, change the published class attribute and alter nothing a visitor sees. It is a vocabulary pass, deferred, and documented here instead.

## Consequences

- **Rollout constraint: code and data change shape together.** The old code reads only `dimension` and the new code only `size` and `spacing`, so there is no window where both render. The order is: back up the database, deploy, run the migration as soon as the new container serves, then restart it. Migrating before the deploy breaks the live site for the length of the build; migrating after the swap breaks it for the length of the script. The restart clears the in-memory ISR and `unstable_cache` entries, because a migration writes rows without calling `revalidatePath`; the admin "Build website" button is the emergency fallback. `docs/self-hosting/08-operations-runbook.md` covers the deploy, backup, restore and rollback rituals this order relies on; the migrate-then-restart step is specific to this change.
- No published page changes appearance: the same variables reach the same element with the same values. The split was checked before the write — a frozen copy of the pre-split getter run against every stored `dimension` matched `getSizeVars` plus `getSpacingVars` on the transform's output for every authored box, with no block falling back on a render default it did not use before.
- An authored box keeps suppressing the block default on both surfaces: the transform's empty marker (`spacing: {}` or `size: {}`) is what says "decided, and empty", and the panel renders it as an empty section with no reset dot.
- No Prisma schema change, no tRPC procedure, no API, no publication or revalidation change: the work stays inside the Puck layer, and the migration is a one-off script rather than a scheduled job.
- The migration reports per row and isolates failures, so a malformed document is named and the rest still convert; a responsive-looking value that is not keyed by breakpoint is preserved and reported rather than dropped.
- Terminology: `GLOSSARY.md` → "Block root" now names the size and spacing variables the root carries, and the split keeps using "Style variable" and "Breakpoint" as written; `docs/puck-canvas.md` names Size and Spacing in the sidebar checklist.
